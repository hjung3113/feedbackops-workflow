# Live TUI is a separate execution mode with adapter-owned session control

Status: accepted

`execution_mode` is a separate axis from the existing permission `mode`: `headless` remains the default, while phase 1 admits `live-tui` only for an implementation seat with write permission. Runtime members own command policy and emit a shell-free launch spec (`argv[]`, `env`, and `prompt_delivery`); transport adapters own session lifecycle and never interpret runtime-specific flags. This keeps the existing headless runner/watchdog path unchanged and prevents a missing live capability from silently falling back to headless.

## Durable live contract

- D1: launch acknowledgement and liveness evidence is `.review/ISSUE-N-launch.*/LIVE.json`. It records ready and prompt-start activity only, never workflow completion.
- D2: `live-session-supervisor.sh` owns the adapter-neutral sequence `wait-ready -> baseline read -> send -> activity`; its settled and canonical-artifact gate functions cover the later `settled -> artifact-gate` phase.
- D3: the launch spec is argv-shaped. Orca's later adapter implementation may join each token with `printf %q` for its required single command string; naive concatenation is not a valid transport.
- D4: Codex live argv explicitly carries `--ask-for-approval never`.
- D5: selection is only `dispatch-core.sh --execution-mode headless|live-tui` in this phase. No workflow-config or model-allocation key selects it.
- D6: transport receipt schema v4 carries `execution_mode`, structured `handles`, and `launch_spec_sha256`. `external_handle` is optional; `runner` is conditional and required only for `execution_mode=headless`. Live receipts do not perform runner hash checks.
- D7: settled classification is normalized to `settled|working|blocked|stale|terminal`. Orca requires post-send activity plus `tui-idle`; Herdr maps its native states directly; cmux can claim settled only with a help-proven agent-state query, otherwise canonical artifact polling remains authoritative and screen matches are diagnostic.
- D8: phase 1 emits `prompt_delivery: transport` for every runtime. `initial-argv` remains an enum slot but is not admitted.
- D9: live partial-work stashing is limited to adapter-reported abnormal termination or a transport disconnect after activity and before a fresh canonical artifact. Blocked and settled-without-artifact are contract failures, not stash triggers.
- D10: Herdr remains a future write-capable transport implementation; T1 defines the shared seam and does not add an adapter-specific Herdr path or exclude it from the eventual write-dispatch set.
- D11: live timeouts are `LIVE_WAIT_READY_TIMEOUT_MS`, `LIVE_SEND_ACTIVITY_TIMEOUT_MS`, `LIVE_WAIT_SETTLED_TIMEOUT_MS`, and `LIVE_SESSION_TIMEOUT_MS`, defaulting to watchdog-scale 240000, 180000, 180000, and 3600000 milliseconds respectively.

The semantic adapter capabilities are `session.live.launch`, `session.ready.wait`, `session.input.send`, `session.output.read`, `session.activity.observe`, `session.state.wait`, `session.interrupt`, and `session.close`. A transport must prove the complete set before live admission; headless availability is reported separately.

## T5 decision gate: does `execution_mode` default flip? (2026-08-22)

**Decision: no default flip. `execution_mode` stays explicit-opt-in `--execution-mode live-tui` (D5), per-adapter, not global, until each adapter has passed its own real-binary verification pass.**

Rationale, by adapter:

- **cmux**: archived (#208, see HANDOFF.md and `toolkit/STATUS.md`). Real cmux 0.64.x lacks the subcommands the T4 adapter assumed; its live capability already fails closed at the capability-probe stage. Not eligible for any default until #208's rewrite lands and is itself real-binary verified. Out of scope for further work until orca/herdr are stable (see the archive note).

- **orca**: partially real-binary verified 2026-08-22 (orca 1.4.188, from inside a live Orca terminal). `capabilities --probe-live`, `launch-live`, `wait-ready`, `read`, `wait-settled`, `send`, and stale-handle detection on `wait-ready`/`wait-settled`/`send` (#206's fix) all behaved correctly against the real binary. That same pass found `read` never inspected the closed-terminal `status:"exited"` field real Orca returns on a zero-exit response, silently returning `{"output":"","cursor":"0"}` instead of a stale signal — filed as #210, and **#210 landed 2026-08-23** (PR #213, merged, smoke-verified with a regression case covering the post-reacquire-still-exited branch too). **#210's fix re-verified against the real orca binary 2026-08-24**: created a real terminal (orca 1.4.188), let it exit, confirmed the exact bug shape live (`terminal read` returns exit 0, `ok:true`, `result.terminal.status:"exited"`, `tail:[]`), then drove the adapter's `read` subcommand directly against that real closed handle — it now fails closed (`ERROR: live_read_failed: terminal read failed`, exit 1) instead of the old silent empty-success. No open defects remain against orca's live adapter.

- **herdr**: real-binary verified 2026-08-22 (herdr 0.8.0, from inside a live Herdr session, real omp/glm-5.3 agent). `capabilities --probe-live` correctly stays headless-only (fail-closed). `read`, `send` (happy path), `inspect`, and stale-handle detection on `read`/`send`/`inspect` after a real workspace close all behaved correctly — no #210-equivalent silent-success bug found here. This pass found two real-binary defects: **#211** — `parse_agent_state` read the wrong JSON field (`.result.agent.status` instead of real herdr's `.result.agent.agent_status`), so `wait_ready` and `wait_settled` always failed even against a genuinely idle agent — **landed 2026-08-23** (PR #214, merged, smoke-verified, not yet re-verified against the real binary). **#211's fix re-verified against the real herdr binary 2026-08-24**: started a real omp agent (herdr 0.8.0, `HERDR_ENV=1` live session), drove the adapter's `wait-ready` and `wait-settled` subcommands directly against it — `wait-ready` returned exit 0 on genuinely `idle`, `wait-settled` correctly returned `{"state":"settled"}` for `idle`/`done`. A genuinely `working` mid-turn state was captured directly from `herdr agent get` (`agent_status:"working"`) and fed through `parse_agent_state`, which classified it correctly (no `*_state_invalid`) — the field-name fix holds for all three lifecycle states against the real binary. **#212 is still open**: the trust-prompt-blocked-launch acceptance test can never pass as constructed (shell command-echo breaks the `\A`-anchored detection rule), and real `agent start` against the same blocked scenario just times out and loses the agent entirely rather than reaching a `blocked` state, so herdr's live launch path has no proven way to survive a first-run trust prompt. **#215 landed 2026-08-23**: for codex launches the trust prompt is now prevented upstream — `launch_live` pre-seeds codex's own per-directory trust store (`[projects."<cwd>"] trust_level = "trusted"` in `$CODEX_HOME/config.toml`) before `agent start`, so the codex trust screen never renders; smoke coverage asserts the TOML-safe merge, idempotency, and that a sentinel codex never hits the trust screen. #215's pre-seed fix (and its round-2 `pre-launch` seam rework, PR #218) has **not** been re-verified against a real codex binary yet — only smoke-verified. #212's underlying detection-manifest defect (`\A` anchor vs shell command echo) remains open for any screen-scraped vendor. Herdr stays ineligible for a default flip until #212 is resolved or explicitly descoped, and until #215/#218's codex pre-seed gets its own real-binary pass.

**Net**: **orca now has a complete real-binary pass with zero open defects** (2026-08-22 initial pass + #210 fix re-verified 2026-08-24) — first adapter to clear this bar; the T5 default-flip decision for orca specifically can be revisited as a follow-up now that this condition is met (still requires an explicit decision, not automatic). Herdr's #211 fix is now also real-binary re-verified (2026-08-24), but herdr as a whole remains ineligible: #212 is still open (design-blocked) and #215/#218's codex trust pre-seed still needs its own real-binary pass. cmux still needs #208 first. Do not flip the global default or move any adapter's default independently of this gate — this record is the authority per D5, supersedes prose in stale handoff files.
